# post-hooks.md

작업 완료 후 결과물을 전달하기 전에 실행하는 검사 목록.
모든 항목을 통과한 결과만 최종 전달한다.

---

## 출력 형식 린트

- [ ] 결과가 체크리스트·diff·요약표 형태로 제시되었는가?
- [ ] 장문 단락으로만 구성된 응답이 아닌가?
- [ ] 변경 파일 목록이 먼저 제시되었는가? (코드 변경 시)
- [ ] `[추정]` 항목이 명시되어 있는가? (불확실한 부분이 있는 경우)

---

## 수락 기준 대조

이슈의 수락 기준과 결과물을 항목별로 대조한다.

```
수락 기준 체크:
- [ ] {수락 기준 1}
- [ ] {수락 기준 2}
- [ ] {수락 기준 3}
```

미달 항목이 있으면 결과를 전달하지 않고 해당 항목을 먼저 처리한다.

---

## 리스크 확인

- [ ] 보안 취약점이 새로 생겼는가? (`[주의]` 표시)
- [ ] 기존 테스트가 깨지는가? (있으면 명시)
- [ ] 새로운 기술 부채가 생겼는가? (있으면 별도 이슈 제안)
- [ ] 운영 환경에서의 위험이 있는가? (있으면 `[주의]` 표시)

---

## 테스트 방법 포함 확인

- [ ] 변경 사항을 검증할 테스트 방법이 제시되었는가?
- [ ] 테스트 명령어 또는 절차가 포함되어 있는가?

---

## 실수 기록 트리거

아래 상황이 발생했으면 `memory/mistakes/`에 기록한다.

- 처음 접근법이 틀려서 방향을 바꾼 경우
- 요구사항을 잘못 해석한 경우
- 예상치 못한 엣지 케이스가 발견된 경우
- 금지 사항을 위반할 뻔한 경우

→ 기록 형식: `memory/mistakes/YYYY-MM-DD-{도메인}-{요약}.md`
