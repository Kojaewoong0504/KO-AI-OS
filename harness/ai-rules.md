# ai-rules.md

AI와 작업할 때 항상 적용되는 규칙.
모든 작업 시작 전 이 파일을 컨텍스트로 주입한다.

---

## 출력 형식 규칙 (최우선)

- 결과는 반드시 **체크리스트, diff, 요약표** 중 하나의 형태로 먼저 제시한다
- 장문 단락으로만 결과를 전달하는 것은 금지
- 설명이 필요하면 요약표 아래에 접을 수 있는 형태로 추가한다
- 코드 변경 시 반드시 변경 파일 목록을 먼저 보여준다

**좋은 예시:**
```
변경 파일: src/filter.py, tests/test_filter.py

체크리스트:
- [x] 신호 필터 로직 분리
- [x] 엣지 케이스 처리
- [ ] 성능 테스트 필요

diff 요약:
+ filter() 함수 추가 (23줄)
- 기존 인라인 필터 로직 제거 (11줄)
```

**나쁜 예시:**
```
안녕하세요! 요청하신 내용을 분석해보겠습니다. 먼저 현재 코드를 살펴보면...
(이하 500자 설명)
```

## 작업 발견 규칙

GitHub Issues가 AI 작업 큐의 정본이다.
새 작업을 GitHub 이슈로 등록할 때는 `harness/github-issue-protocol.md`를 따른다.

작업 가능 이슈 쿼리:

```text
is:issue is:open label:ai-task label:ready-for-ai -label:needs-clarification -label:blocked
```

- `ai-task`: AI가 처리할 수 있는 작업
- `ready-for-ai`: pre-hook을 통과해 작업 가능한 상태
- `needs-clarification`: 목적·수락 기준·범위가 부족해 작업 금지
- `blocked`: 외부 입력이나 의존성 때문에 작업 금지

작업 시작 전에는 가장 오래된 `ready-for-ai` 이슈를 우선 확인한다.
사용자가 특정 이슈 번호나 우선순위를 지정하면 그 지시를 우선한다.
이슈 본문과 코멘트를 읽고, 수락 기준을 완료 계약으로 삼는다.

---

## 작업 전 규칙

- 구현 전에 반드시 요구사항에서 빠진 항목을 먼저 질문한다
- 불명확한 부분은 추정이라고 표시한다 (`[추정]` 태그 사용)
- 접근법이 2가지 이상 가능하면 표로 비교 후 추천안을 제시한다
- 범위를 벗어나는 작업은 별도 이슈로 분리 제안한다

---

## 작업 중 규칙

- 한 번에 하나의 관심사만 변경한다
- 기존 동작을 바꾸는 변경은 반드시 명시한다
- 확실하지 않은 부분은 `[추정]`으로 표시하고 계속 진행한다
- 보안·성능·운영 리스크가 있으면 `[주의]` 태그로 별도 표시한다

---

## 작업 후 규칙

- 결과물은 이슈의 수락 기준과 대조해 체크리스트로 보고한다
- 테스트 방법을 반드시 함께 제시한다
- 이 작업으로 새로 생긴 기술 부채가 있으면 명시한다

---

## 금지 사항

- 요청하지 않은 범위의 코드 수정 금지
- 기존 테스트를 삭제하거나 우회하는 방식 금지
- 환경변수·시크릿 하드코딩 금지
- 에러를 조용히 삼키는 코드 (`except: pass` 등) 금지

---

## 도메인 컨텍스트

- 주 작업 도메인: 서비스 기획·개발, 트레이딩 시스템
- 자동화 가능성을 항상 먼저 검토한다
- 시스템 경계(무엇이 안이고 밖인지)를 먼저 정의한다
